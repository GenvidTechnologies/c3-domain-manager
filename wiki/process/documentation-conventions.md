# Documentation Conventions

> Moved verbatim out of `CLAUDE.md`'s "Documentation conventions" section to keep
> the session-loaded instruction files under Claude Code's 150k-character limit.
> **Throughout this page, "this file" and "here" mean `CLAUDE.md`**, where these
> rules were written. `CLAUDE.md` keeps a short summary and points here.

Docs under `wiki/` (especially ADRs in `wiki/decisions/`) are committed and read by people who do not share this machine. Several rules follow:

- **There are now two documentation tiers: this file, and the wiki bundle at `wiki/`.** `docs/` is not a third tier anymore — it was folded *into* the bundle (see Documentation layout above), so `wiki/decisions/`, `wiki/reference/`, and `wiki/process/` now hold the same source-of-record content `docs/` used to. What still distinguishes a **wiki page** proper — `wiki/index.md`, `wiki/schema.md`, `wiki/log.md`, and topic-synthesis pages like `wiki/fs-watch-platform-behaviour.md` — from that source-of-record content sitting beside it is that every claim on a wiki page states where it came from. An ADR is scoped to one decision at one moment, so knowledge spanning several records — what `fs.watch` does per platform, when to route a fix upstream — used to have nowhere to live but *this file*, where it drifts. A wiki page is a summary that carries per-claim footnotes resolving through frontmatter `sources[]` to a fixed artifact, which is exactly what the drift instances below lacked. `wiki/schema.md` is the maintenance contract; `/gvt-dev:maintain-wiki` is the interface (`ingest` / `query` / `lint`). Two rules are load-bearing and easy to violate without seeing them: **in-repo records are cited directly, never snapshotted into `raw/`** (git already provides that immutability, and a snapshot is a second copy that drifts from the record it copies) — this rule has more force since the move, not less, because the records a wiki page cites now live *inside* the bundle those pages sit in, so every `sources[]` value resolves within `wiki/` rather than dangling out to a separate `docs/` tree. And **`CLAUDE.md` is not citable as a source** — it is rewritten continuously, so a page citing it cannot be re-verified against a fixed text, which is the one property `sources[]` exists to guarantee. A claim worth a wiki page and found only here needs an ADR or an issue behind it first. Note also that **nothing automatic checks wiki link health or staleness**: `lint` is on-demand and is deliberately never wired into `audit-conventions`, so that wiki content can never move a contract audit's exit code (issue #72).

- **A sentence in *this* file that characterizes an ADR's *framing* is a second copy of that ADR, and it drifts.** Citing a record by number is safe; paraphrasing what it *decided* is not — the paraphrase reads with the record's authority while carrying none of its text, and nothing compares the two. So quote the record, or `grep` the paraphrase against it before relying on it. This is not hypothetical and the cost is not small: **`SECTION_SOURCE_EXTENSIONS` was described here for months as "product policy, local by decision — derived from what `computeDomainData` parses, not from what C3 permits on disk," a phrase that appears nowhere in ADR 0020.** ADR 0020 decided the opposite — it adopted `.json` as *"c3source's own documented convention, not inventing a new one."* The gloss survived long enough to shape issue #60's problem statement, a requirements analysis, and a design before one `grep` settled it (ADR 0022). Note which way the error ran: the *record* was right and the *summary* was wrong, so a reader trusting this file over `wiki/decisions/` got it backwards — the reverse of the staleness this file usually warns about.

- **The same rule holds *between* records, which is the larger surface — an ADR paraphrasing a sibling's reasoning is a second copy too.** The bullet above is written about *this* file, and that scoping reads as the whole rule; it is not. Sibling citation is near-universal (22 of 23 records carry a `[[slug]]`), so record-to-record paraphrase happens far more often than `CLAUDE.md`-to-record paraphrase does. Citing a sibling's *conclusion* is safe. Restating the *route it took* is not — and **two records reaching the same answer by different arguments is the common case, not the exception**, so the paraphrase that feels safest (the conclusions match, after all) is exactly the one that silently swaps mechanisms. ADR 0023 credited ADR 0020 (`wiki/decisions/0020-section-source-extension-filter.md`) with a manifest-position argument — a name section keys its items on `<name>.json`, so a stray has no position to acquire — that appears nowhere in it; `grep` finds no keying reasoning in ADR 0020 at all. Its actual route was that nothing downstream can represent the file, so no `overrides` entry could usefully change anything. The keying argument is *upstream's*, and the two are not interchangeable: one is about C3 manifest position, the other about this tool's index representation. Caught in review before merge (issue #62). So: `grep` the sibling before attributing a mechanism to it, and where two records agree by different routes, **say that** rather than collapsing one into the other. Note this bullet and the one above are the same failure at two altitudes — the fix for both is that a citation carries authority the citing text has not earned until someone compares them, and nothing does that automatically.

- **A third shape needs no second artifact at all — a bolded headline that overreaches the paragraph it introduces.** The two bullets above each compare a summary against a *separate* record, which at least tells you what to `grep`. This one is self-contained, and so has no natural prompt to check it: the section-enumeration paragraph's headline used to assert not just that each section has one enumeration but that *every reader goes through it* — while the same paragraph stated, eight sentences later, **"The invariant is the number of enumerations, not the number of readers"**, and that adding a reader is fine and expected. (The retired clause is quoted verbatim in `b64ef18`; it is deliberately not reproduced here, because a criterion pinned to its absence is what proves it gone.) The headline clause had zero support in `wiki/decisions/`, and the qualifier contradicting it was *already present* and still did not prevent the misframing — because a headline is what a reader orients on and the body is what they skim. It sent issue #37 into a requirements analysis and a design resting on a premise three accepted records deny, unwound only by reading those records directly ([ADR 0024](wiki/decisions/0024-editor-validation-single-enumeration.md)). So: a bolded claim in this file is load-bearing in a way the sentences beneath it are not, and when a paragraph qualifies its own headline, the headline is the thing to fix — not the qualifier to add.

- **A fourth shape: a dispatch brief is a paraphrase too, and it is the one the reader cannot check.** The three above all end up in a committed file, where a later reader can at least `grep` them. A brief handed to a subagent never lands anywhere — it is consumed once, by a context that has no independent access to what it summarizes and every reason to treat it as authoritative. Measured in issue #72: a brief dispatching `tech-writer` to author `wiki/documentation-drift-modes.md` supplied three worked examples drawn from *this file*; on reading the records, **two of the three did not exist in the ADRs the brief attributed them to** — one described an error caught in review before merge, so the merged record is clean, and one traced to a `CLAUDE.md` sentence with no ADR behind it at all. Both were replaced with ADR-traceable equivalents. What caught it was a single instruction in the brief telling the agent to read the ADRs and write from them rather than from the brief's summary; without that line the fabricated attributions would have shipped *inside the page about fabricated attributions*. So: name the primary sources in a brief and require the agent to read them — never let a summary in the brief stand in for the record, and treat a brief that says "the ADR decided X" as owing the same `grep` as a sentence in this file would.

- **Never cite a machine-local path.** Design work here is often validated against real Construct 3 projects checked out locally. Those measurements are valuable and belong in an ADR — but cite the *measurement and the project's characteristics* ("a large domain-foldered project, C3 r47604, 245 `.uistate.json` files"), never the path (`C:\repos\<name>`). A reader cannot follow the path, and the checkout may not survive.
- **Verify every cross-reference before writing it.** A link or section name that does not exist is worse than no citation — it sends the next reader hunting. This bit issue #33: a drafted ADR cited a `CLAUDE.md` section named "Real C3 project corpus" that has never existed in this file. Auto-memory and `<system-reminder>` content sit in the same context window as repo content but are **not** part of the repo; treat them as input you may act on, never as something you may cite. `grep` the target file before asserting a section exists.

- **ADR cross-references use `[[<adr-slug>]]`, not markdown links.** A sibling record is cited as `[[0011-expression-reference-coupling]]` — bare filename stem, double brackets, no path, no `.md`. Prose references by number (`ADR 0013`) coexist and are equally fine. **Do not "normalize" the bracket form away:** it is the house style in every record but one (`0008-adopt-openproject-option-a`, currently 22 of 23), not a stray. This is easy to get backwards, because auto-memory files use the same `[[name]]` syntax for *their* links — so the form reads like a leak from outside the repo, the mirror image of the trap in the bullet above. Check `wiki/decisions/` before concluding a convention is foreign; a two-file sample is not the corpus. **The form stops at that directory, though — it is how a *record cites a record*, not a repo-wide link style.** Prose docs cite ADRs by path: `wiki/reference/domain-architecture.md` does so at all six of its citation sites, and `README.md` carries none. So a `[[slug]]` reaching a non-ADR doc is over-application, not adoption — the failure mode is the mirror of the one this bullet already warns about, and it happened in issue #39 (caught in review, one line).

- **In a code comment, cite the *symbol*, not a line range.** The bullets above are about prose drifting from a record; this one is about a citation drifting from *code*, which decays far faster and is invisible to every gate here — lint, typecheck and the full suite stay green because nothing reads comment prose. Measured: `test/mcp/writeFailure.test.ts`'s citation of the config-path watch handler went stale **twice in two days** — corrected `server.ts:598-606` → `602-610` in issue #68's first branch commit, then invalidated again one commit later by the `OptimisticWatcher` adoption, which moved the handler again. Re-numbering only resets the clock; a symbol name (`onExternalChange`) survives every edit that does not rename it, and a rename is exactly when the next reader should be looking anyway. **Two carve-outs.** ADRs are exempt — a record documents state at decision time, so "correcting" its line numbers falsifies it rather than maintaining it (`wiki/decisions/0025-*.md` cites `server.ts:34-40`, now stale, and is deliberately left alone). And `file:line` in *this* file, in an issue body, or in a dispatch brief is fine: those are working references read once, not committed alongside the code they point at.

- **When a path moves, sweep by asking what each reference *is*, not which file it sits in — and when part of a file is frozen, name the boundary rather than the file.** The bullet above is about a citation decaying in place; this one is about which citations to update at all. A reference is either **a link target that must resolve** (repoint it) or **a retired path named in prose as history** (leave it exactly as written) — a record documents state at decision time, so sweeping it falsifies the record. `wiki/decisions/0027-retire-docs-tier-into-the-wiki-bundle.md` applied that split across 116 occurrences when `docs/` was retired; a mechanical regex sweep was rejected because it cannot tell the two apart and would have corrupted 25 historical ones. **The trap is the second clause, because whole-file instructions read as complete and are not.** `wiki/log.md` is part-frozen: its dated entries are frozen by its own append-only rule, while its preamble — sitting *above* the first `## YYYY-MM-DD` heading — is live maintenance prose that had to be repointed, or the log would permanently direct readers at a dead path. `CHANGELOG.md` has the identical shape and it was missed: a sweep told *"the released sections are history"* correctly left the whole file, and its preamble kept pointing at `docs/releasing.md` until a follow-up commit (`52892c5`) caught it. Same structure, two files, one right and one wrong — so state the frozen span, never the filename.

- **A `grep` miss is not evidence of absence — check the pattern before concluding the doc is silent.** This file is dense with `**bold**`, backticks and em-dashes, so a plain-looking phrase often carries markup mid-token. A retro this file prompted nearly proposed re-adding the "a dependency major can land **mid-task**" rule as a gap, because the grep for it spanned the `**` and returned nothing — the rule was already here, three lines from where the addition would have gone. Anchor on a distinctive unbroken substring, or `grep -c` a couple of variants, before writing "not documented".

- **The inverse also holds, and it is the easier one to walk into: a `grep` *hit* is not evidence of survival.** The bullet above is about a check that wrongly reports absence; this is about one that wrongly reports presence, and it fires whenever you verify that something was *retired*. A correction record quoting the wording it replaced, a CHANGELOG explaining a rename, an ADR quoting the sentence it supersedes, and prose that says a symbol *was retired* all legitimately contain the retired form — so a zero-hit check over them fires on text that is doing its job, and reads as "the change didn't land". The remedy is not a cleverer pattern: **`grep -n` and read where the survivor sits**, rather than comparing a count to zero. Measured in issue #77, five times in one session, every one while the same rule was being enforced on a subagent — including a criterion of the orchestrator's own writing that required a symbol be gone from a file *and*, two paragraphs later, required a docstring in that file to name it. The two instructions were not reconcilable and neither was wrong; the zero was.

- **Six optional `audit-conventions` doc expectations are unmet by decision, not by neglect** — `docs/architecture.md`, `docs/design-patterns.md`, `docs/coding-conventions.md` (declared by `ts-implementer`) and `docs/code-review-{context,patterns,docs}.md` (declared by `code-reviewer`). Every audit run lists all six under `### Info (optional)`, which reads as a backlog. It is not one: that content lives in this file and in `wiki/reference/domain-architecture.md`, and splitting it out would create exactly the second-copy-that-drifts problem the bullets above are about. All six are declared `required: false` precisely so a repo that keeps the content elsewhere still passes. Leave them absent unless the content genuinely diverges from what this file carries.
